# git-commit — 변경을 내용별로 묶어 순차 커밋

## 절차

1. **분석**: `git status`, `git diff`로 변경을 읽고 내용별로 묶는다.
   - rename/remove는 단독 커밋.
   - 그 외는 기능·연관성 단위로 묶는다. 코드와 그 코드가 만든 산출물은 분리한다.
2. **제안**: 그룹을 아래 형식으로 보여주고 확인받는다. 그룹이 둘 이상이면 순번과 묶은 근거 한 줄을 붙인다.

   ```
   C1 — [type] scope — 한 줄 요약
   | 파일 | 변경 |
   | 경로 | M / D / A + 무엇이 바뀌었는지 |
   ```

3. **커밋**: 승인된 순서대로 그룹별로 `git add <경로>` → 커밋. `git add -A`/`git add .`과 그룹 경계를 넘는 스테이징은 하지 않는다.
4. **보고**: 커밋 해시·제목·파일 수. 푸시는 요청 시에만.

## 메시지 형식

```
[type] scope — 한국어 한 줄 요약

왜 필요했는지 → 무엇을 했는지 순서로. 항목이 여럿이면 `- ` 목록.

Co-Authored-By: Claude <noreply@anthropic.com>
```

- **type**: `feat` · `fix` · `refactor` · `docs` · `chore` · `rename` · `data`(스크립트가 만든 산출물)
- **scope**: 변경 영역(폴더나 기능 이름). 여러 영역이면 `·`로 연결.
- 본문에는 diff가 말해주지 않는 **이유**를 쓴다. 변경 파일 목록 나열은 하지 않는다.
